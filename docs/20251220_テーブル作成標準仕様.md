# テーブル作成標準仕様

**作成日:** 2025年12月20日  
**対象:** marumieプロジェクト - バックエンドデータベース設計

## 1. 概要

本プロジェクトにおけるSQLAlchemyモデル（テーブル定義）を作成する際の標準仕様を定義する。
一貫性のあるデータベース設計を維持し、メンテナンス性・可読性を向上させることを目的とする。

## 2. 必須フィールド

### 2.1 主キー (`id` または `key`)

すべてのテーブルに主キーを設定する。命名規則は以下の通り：

#### パターンA: UUID文字列主キー (`id`)
- **使用ケース:** 通常のエンティティテーブル（User, Organization, PersonalTransactionなど）
- **型:** `String(36)`
- **デフォルト値:** `uuid4()` で自動生成
- **実装:** `UUIDIdMixin` を継承

```python
from .mixins import UUIDIdMixin

class User(UUIDIdMixin, TimestampMixin, Base):
    __tablename__ = "users"
    # id フィールドは UUIDIdMixin から自動継承
```

#### パターンB: 文字列キー主キー (`key`)
- **使用ケース:** マスタテーブル（Categoryなど、外部から参照される固定的な識別子を持つテーブル）
- **型:** `String(100)` （長さは要件に応じて調整）
- **明示的設定:** ビジネスキーを直接主キーとして使用

```python
class Category(TimestampMixin, Base):
    __tablename__ = "categories"
    
    key: Mapped[str] = mapped_column(
        String(100),
        primary_key=True,
        nullable=False,
        comment="カテゴリキー（主キー・一意識別子）",
    )
```

### 2.2 名前フィールド (`name`)

すべてのテーブルに人間が読みやすい名前フィールドを含める。

#### 基本実装

```python
name: Mapped[str] = mapped_column(
    String(255),
    nullable=False,
    comment="名前"
)
```

#### 表示名が別途必要な場合

システム内部名と表示用名称を分離する場合、両方を定義：

```python
name: Mapped[str] = mapped_column(
    String(255),
    nullable=False,
    comment="システム内部名"
)
display_name: Mapped[str] = mapped_column(
    String(255),
    nullable=False,
    comment="表示名"
)
```

**例:** `Organization` テーブル
- `name`: `"yamada_taro_seijishikin"`（内部識別用）
- `display_name`: `"山田太郎政治資金管理団体"`（UI表示用）

### 2.3 タイムスタンプ (`created_at`, `updated_at`)

すべてのテーブルに作成日時・更新日時を記録する。

- **実装:** `TimestampMixin` を継承
- **自動設定:** データベース側で自動管理（`server_default`, `onupdate`）

```python
from .mixins import TimestampMixin

class YourModel(TimestampMixin, Base):
    __tablename__ = "your_table"
    # created_at, updated_at は TimestampMixin から自動継承
```

## 3. Mixin継承順序

SQLAlchemyモデルクラス定義時は以下の順序でMixinを継承する：

```python
class ModelName(UUIDIdMixin, TimestampMixin, Base):
    # または
class ModelName(TimestampMixin, Base):  # key主キーの場合
```

**順序ルール:**
1. `UUIDIdMixin` （主キーがUUIDの場合のみ）
2. `TimestampMixin` （必須）
3. `Base` （必須・最後）

## 4. テーブル定義テンプレート

### 4.1 標準エンティティテーブル（UUID主キー）

```python
from __future__ import annotations

from sqlalchemy import String, Text, Boolean
from sqlalchemy.orm import Mapped, mapped_column

from .base import Base
from .mixins import UUIDIdMixin, TimestampMixin


class YourModel(UUIDIdMixin, TimestampMixin, Base):
    """テーブルの説明
    
    このテーブルの目的、保持するデータの概要を記述。
    """
    
    __tablename__ = "your_table_name"
    
    # id, created_at, updated_at は Mixin から自動継承
    
    name: Mapped[str] = mapped_column(
        String(255),
        nullable=False,
        comment="名前"
    )
    
    description: Mapped[str | None] = mapped_column(
        Text,
        nullable=True,
        comment="説明"
    )
    
    is_active: Mapped[bool] = mapped_column(
        Boolean,
        nullable=False,
        default=True,
        server_default="true",
        comment="有効フラグ"
    )
```

### 4.2 マスタテーブル（key主キー）

```python
from __future__ import annotations

from sqlalchemy import String, Integer, Boolean
from sqlalchemy.orm import Mapped, mapped_column

from .base import Base
from .mixins import TimestampMixin


class YourMaster(TimestampMixin, Base):
    """マスタテーブルの説明
    
    このマスタテーブルの目的、保持するマスタデータの概要を記述。
    """
    
    __tablename__ = "your_master_table"
    
    key: Mapped[str] = mapped_column(
        String(100),
        primary_key=True,
        nullable=False,
        comment="マスタキー（主キー）",
    )
    
    name: Mapped[str] = mapped_column(
        String(255),
        nullable=False,
        comment="名前"
    )
    
    display_order: Mapped[int] = mapped_column(
        Integer,
        nullable=False,
        default=999,
        comment="表示順序"
    )
    
    is_active: Mapped[bool] = mapped_column(
        Boolean,
        nullable=False,
        default=True,
        server_default="true",
        comment="有効フラグ"
    )
```

## 5. 命名規則

### 5.1 テーブル名

- **形式:** スネークケース、複数形
- **例:** `users`, `organizations`, `personal_transactions`, `categories`

```python
__tablename__ = "table_names"
```

### 5.2 カラム名

- **形式:** スネークケース
- **例:** `user_id`, `created_at`, `display_name`, `is_active`

```python
user_id: Mapped[str] = mapped_column(
    String(36),
    ForeignKey("users.id"),
    name="user_id"  # DB上のカラム名を明示的に指定
)
```

### 5.3 外部キー命名

- **形式:** `{参照先テーブル単数形}_id`
- **例:** `user_id`, `organization_id`, `category_key`

```python
organization_id: Mapped[str] = mapped_column(
    String(36),
    ForeignKey("organizations.id", ondelete="CASCADE"),
    nullable=False,
    name="organization_id"
)
```

## 6. 推奨フィールド

必須ではないが、多くのテーブルで有用なフィールド：

### 6.1 論理削除フラグ

```python
is_active: Mapped[bool] = mapped_column(
    Boolean,
    nullable=False,
    default=True,
    server_default="true",
    comment="有効フラグ（論理削除用）"
)
```

### 6.2 表示順序

UI上の並び順を制御する場合：

```python
display_order: Mapped[int] = mapped_column(
    Integer,
    nullable=False,
    default=999,
    comment="表示順序"
)
```

### 6.3 説明・メモ

```python
description: Mapped[str | None] = mapped_column(
    Text,
    nullable=True,
    comment="説明"
)

memo: Mapped[str | None] = mapped_column(
    Text,
    nullable=True,
    comment="メモ"
)
```

## 7. インデックス設定

パフォーマンス向上のため、適切にインデックスを設定する：

```python
from sqlalchemy import Index

class YourModel(UUIDIdMixin, TimestampMixin, Base):
    __tablename__ = "your_table"
    
    # フィールド定義...
    
    __table_args__ = (
        Index("ix_your_table_user_id", "user_id"),
        Index("ix_your_table_created_at", "created_at"),
        Index("ix_your_table_user_id_type", "user_id", "type"),  # 複合インデックス
    )
```

**インデックス命名規則:** `ix_{テーブル名}_{カラム名1}_{カラム名2}`

## 8. コメント設定

すべてのカラムに `comment` パラメータを設定し、DDL上で説明を記載：

```python
name: Mapped[str] = mapped_column(
    String(255),
    nullable=False,
    comment="ユーザー名"  # ← 必ず設定
)
```

データベースツールでスキーマを確認した際に、カラムの用途が明確になる。

## 9. Type Hints (型ヒント)

SQLAlchemy 2.0スタイルの `Mapped` 型ヒントを使用：

```python
# ✅ 推奨
name: Mapped[str] = mapped_column(String(255), nullable=False)
amount: Mapped[Decimal] = mapped_column(Numeric(15, 2), nullable=False)
description: Mapped[str | None] = mapped_column(Text, nullable=True)

# ❌ 非推奨（古いスタイル）
name = Column(String(255), nullable=False)
```

**Nullable対応:**
- `Mapped[str]`: NOT NULL
- `Mapped[str | None]`: NULL許可

## 10. Enum型の使用

状態や種別を表すフィールドには文字列リテラルではなくEnum型を使用：

```python
from sqlalchemy import Enum
from .enums import YourEnumType  # app/models/enums.py で定義

class YourModel(UUIDIdMixin, TimestampMixin, Base):
    __tablename__ = "your_table"
    
    type: Mapped[YourEnumType] = mapped_column(
        Enum(
            YourEnumType,
            name="your_enum_type",
            values_callable=lambda x: [e.value for e in x]
        ),
        nullable=False,
        comment="種別"
    )
```

**Enum定義例 (`enums.py`):**

```python
from enum import Enum as PyEnum

class YourEnumType(str, PyEnum):
    TYPE_A = "type_a"
    TYPE_B = "type_b"
    TYPE_C = "type_c"
```

## 11. リレーションシップ定義

外部キー関連付けがある場合、`relationship` を設定：

```python
from sqlalchemy.orm import relationship

class Organization(UUIDIdMixin, TimestampMixin, Base):
    __tablename__ = "organizations"
    
    user_id: Mapped[str | None] = mapped_column(
        String(36),
        ForeignKey("users.id", ondelete="SET NULL"),
        name="user_id"
    )
    
    # リレーションシップ定義
    user: Mapped[User | None] = relationship(back_populates="organizations")
    personal_transactions: Mapped[list[PersonalTransaction]] = relationship(
        back_populates="organization",
        cascade="all, delete-orphan",
        passive_deletes=True
    )
```

**双方向リレーションシップ:**
- 親側: `back_populates` で子側のリレーション名を指定
- 子側: `back_populates` で親側のリレーション名を指定

## 12. マイグレーション作成手順

1. **モデル定義作成:** `backend/app/models/` に新規ファイル作成
2. **models/__init__.py に追加:** モデルをエクスポート

```python
from .your_model import YourModel

__all__ = [
    # ... 既存モデル
    "YourModel",
]
```

3. **マイグレーションファイル生成:**

```bash
cd backend
uv run alembic revision --autogenerate -m "add_your_table"
```

4. **マイグレーションファイル確認・編集:**
   - `backend/alembic/versions/` に生成されたファイルを確認
   - 必要に応じて初期データ投入を追加

```python
def upgrade() -> None:
    # テーブル作成
    op.create_table(...)
    
    # 初期データ投入（オプション）
    op.execute(
        """
        INSERT INTO your_table (key, name, is_active) VALUES
        ('key1', 'Name 1', true),
        ('key2', 'Name 2', true);
        """
    )

def downgrade() -> None:
    op.drop_table('your_table')
```

5. **マイグレーション実行:**

```bash
uv run alembic upgrade head
```

## 13. チェックリスト

新しいテーブルを作成する際、以下を確認：

- [ ] 主キーが設定されている（`id` または `key`）
- [ ] `name` フィールドが存在する
- [ ] Mixinを適切に継承している（`UUIDIdMixin` / `TimestampMixin`）
- [ ] すべてのカラムに `comment` が設定されている
- [ ] 型ヒント (`Mapped[T]`) を使用している
- [ ] Nullable/NOT NULLが適切に設定されている
- [ ] 外部キーがある場合、`ondelete` が指定されている
- [ ] 頻繁に検索されるカラムにインデックスが設定されている
- [ ] Enum型が適切に使用されている
- [ ] モデルが `models/__init__.py` にエクスポートされている
- [ ] マイグレーションファイルが生成され、レビュー済み
- [ ] マイグレーションが実行され、テーブルが作成されている
