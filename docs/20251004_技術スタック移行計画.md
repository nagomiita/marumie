# Vite + React + FastAPI + SQLAlchemy + Orval 技術スタック移行計画

## 背景と目的
- 現行のフロント／バックエンド構成を、ビルド速度と開発者体験を重視した **Vite + React**、API サーバーを **FastAPI**、データアクセスを **SQLAlchemy**、型安全なクライアント生成に **Orval** を採用する形へ置き換える。
- 既存機能（ダッシュボード、CSV 変換フロー、年/月切替 UI、キャッシュ制御など）を維持したまま段階的に移行し、ダウンタイムを最小化する。

## スコープ
- フロントエンド: webapp 全体を Vite + React へ移行し、SSR/CSR の方針を決定する。
- BFF/API: Next.js API など既存サーバー層を FastAPI に置き換え、OpenAPI 契約を公開する。
- データ層: Prisma 依存箇所を SQLAlchemy へ移行し、既存 DB スキーマを踏襲。
- クライアント生成: OpenAPI 仕様から Orval で型付き API クライアントを自動生成し、フロントの fetch ロジックを差し替える。

## 前提・非ゴール
- 認証やインフラ（DB/ストレージ）は現行を引き継ぐ。変更が必要な場合は別途チケット化。
- 新機能追加は行わず、あくまで技術スタック置き換えに集中する。

## 実装順序（タスク分解）
1. **現行アーキテクチャの棚卸し**
   - API エンドポイント一覧と入出力形式を洗い出し、FastAPI で再現すべき機能を確定する。
   - フロントで依存しているデータ取得箇所（fetcher、React Query など）とキャッシュ戦略を整理。

2. **FastAPI プロジェクトの雛形作成**
   - `backend/` に FastAPI アプリを初期化し、環境変数・設定ロード方針を決定。 ✅
   - 依存パッケージ（FastAPI、Uvicorn、SQLAlchemy、pydantic、alembic など）を追加し、起動確認を取る。 ✅
   - `/health` エンドポイントで最小の起動確認ができる状態にする。 ✅

3. **DB アクセス層の SQLAlchemy への移行**
   - 既存 Prisma スキーマをベースに SQLAlchemy モデルを定義。
   - セッション管理、マイグレーション（alembic）のセットアップ。
   - 代表的なリポジトリ/ユースケース（例: トランザクション取得、集計計算）を SQLAlchemy で実装し、ユニットテストを追加。

4. **FastAPI で OpenAPI 契約を公開**
   - 主要エンドポイントを FastAPI で実装し、`/openapi.json` を正として管理。
   - 認証・エラーハンドリングの共通レスポンススキーマを整備し、既存 UI で必要なフィールドが揃うことを確認。

5. **Orval によるクライアント生成パイプライン構築**
   - `orval.config.ts`（または同等）を作成し、FastAPI の OpenAPI からクライアントを生成する設定を追加。
   - CI もしくは `pnpm orval` などのスクリプトで再生成を自動化し、型定義をフロントの参照元に設定。

6. **Vite + React フロントエンドの立ち上げ**
   - `webapp` を Vite + React プロジェクトとして再初期化し、既存コンポーネント・スタイルを移植。
   - 環境変数、ルーティング（React Router など）、状態管理の方針を決定し、最小限のページを起動確認。

7. **API 呼び出しの Orval クライアント差し替え**
   - 既存の fetch/axios ラッパーを Orval 生成クライアントに置き換え、型エラーを解消。
   - キャッシュ制御（開発環境での無効化・リフレッシュボタン連携）を新クライアントで再実装。

8. **機能単位での段階的移行と E2E 確認**
   - トップページ（年/月セレクター、グラフ群、トランザクション一覧）→ 管理画面 → CSV 変換フローの順で移行し、機能ごとに E2E / UI テストを実施。
   - 「データが存在しません」などの UI 仕様が新スタックでも維持されることを確認。

9. **デプロイ・運用更新**
   - 新バックエンドのデプロイ手順（Uvicorn/Gunicorn、コンテナ設定）とフロントのビルド/配信手順を整備。
   - 環境変数・CI/CD 設定を更新し、ロールバック手順を明記。

## 進捗状況

- FastAPI 雛形を `backend/` に追加し、設定ロードと DB セッションファクトリを実装。
- `/health` エンドポイントで起動確認可能。
- Prisma スキーマを SQLAlchemy モデルへ移植し、初期マイグレーションを Alembic で追加。
- 次のステップ: Alembic を本番 DB に適用するための接続確認、OpenAPI スキーマ定義、Orval の生成パイプライン整備。

## 成果物
- FastAPI ベースの API サーバー（OpenAPI 公開）と SQLAlchemy モデル群。
- Orval 生成の型付きクライアントと、それを利用する Vite + React フロントエンド。
- デプロイ・運用手順を含む更新済みドキュメント。
